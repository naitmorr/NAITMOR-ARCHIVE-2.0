# Техническая архитектура

Утверждённая основа NAITMOR // ARCHIVE 2.0: Astro, TypeScript strict,
статический HTML и публикация в подкаталоге GitHub Pages через GitHub Actions.

## Границы этапа 1

Реализованы конфигурация проекта, общий HTML-шаблон, техническая главная,
страница 404, палитра CSS-переменных и функция внутренних URL.
Локальные файлы шрифтов, интерфейс разделов и клиентская интерактивность
относятся к следующим этапам. До подключения шрифтов используются системные.

## Разделение ответственности

- `content/`: авторские материалы без логики интерфейса.
- `schemas/` и `content.config.ts`: будущая валидация и типизация коллекций.
- `assets/images/`: изображения, обрабатываемые Astro при сборке.
- `public/`: файлы, которые нужно копировать без обработки.
- `config/`: технические настройки и будущая навигация.
- `lib/`: общие выборки и вспомогательные функции.
- `layouts/`: структура HTML-документа и страниц.
- `components/`: переиспользуемый интерфейс по назначению.
- `pages/`: маршруты, связывающие данные и компоненты.
- `scripts/` внутри `src/`: будущие клиентские сценарии.
- `scripts/` в корне: инструменты проверки проекта.

## Подготовленные коллекции

`characters`, `lore`, `events`, `releases`, `tracks`, `artworks`, `news`, `dossiers`.
Схемы и загрузчики будут зарегистрированы на этапе 2. Сейчас экспорт коллекций
пуст, а в каталогах нет авторских или демонстрационных записей.

Альбомы, EP и синглы будут храниться в `releases` с полем типа.
Треки образуют отдельную коллекцию; порядок треклиста принадлежит релизу.
CLASSIFIED соответствует `dossiers` и является публичным сюжетным архивом.

## Маршруты

Подготовлены каталоги `characters`, `lore`, `timeline`, `music/releases`,
`music/tracks`, `gallery`, `classified`, `news`. Их страницы появятся
после реализации моделей контента и интерфейса; пустые каталоги не создают URL.

Astro формирует статическую сборку в `dist/`. Canonical URL строится
от настроенного `site`, внутренние ссылки — через `withBase()`.
Проверка `npm run check:pages` контролирует префикс проекта в собранном HTML.

## Воспроизводимость

Версия Node.js закреплена в `.node-version`, прямые зависимости — в `package.json`,
полное дерево — в `package-lock.json`. В CI и при повторной установке используется
`npm ci`. Для проверки Astro и TypeScript предназначен `npm run check`.

Публикация отделена от CI и имеет только ручной триггер.
