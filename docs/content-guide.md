# Работа с контентом

Контент проходит одни и те же строгие Zod-схемы в Astro Content Collections
и в самостоятельной проверке. Для новых записей не требуется менять компоненты.

## Инструкции

- [Персонаж](content/characters.md).
- [Альбом и трек](content/music.md).
- [Событие хронологии](content/timeline.md).
- [Арт](content/gallery.md).

## Каталоги и форматы

Используются семь коллекций: `characters`, `lore`, `timeline`, `music`,
`gallery`, `news`, `dossiers`. Внутри каждой — отдельные каталоги `ru/` и `en/`.

Путь записи: `src/content/<collection>/<locale>/<entryKey>.<extension>`.
Например, `src/content/characters/ru/demo-character-alpha.md`.
ID в коллекции: `ru/demo-character-alpha`.

Допустимы `.md`, `.mdx`, `.json`, `.yaml`, `.yml`. Один файл данных — одна запись,
не массив записей. Markdown/MDX содержат YAML-frontmatter и непустой основной текст;
JSON/YAML подходят для структурированных карточек и метаданных без основного текста.

MDX подключён через совместимую интеграцию Astro. Редакционный MDX допускает
статические HTML-элементы: `aside`, `span`, `em`, `strong`, `p`, `section`, `div`,
`blockquote`, `br`, `a`, `img`. Импорты, экспорты, исполняемые выражения, обработчики
событий и динамические атрибуты не допускаются. Для новых типов интерактивных блоков
сначала нужно расширить программный слой. Обычный Markdown не допускает сырой HTML.

Старые пустые `events/`, `releases/`, `tracks/`, `artworks/` сохранены без удаления
файлов. Они не являются коллекциями. Проверка завершится ошибкой, если добавить
туда запись вместо актуальных `timeline/`, `music/`, `gallery/`.

## Общие правила

Обязательны `locale`, `entryKey`, `translationKey`, `title`, `summary`.
`entryKey` и `translationKey` используют латиницу в нижнем регистре, цифры и дефисы.
Ключ записи совпадает с именем файла; изменение заголовка не изменяет ID.
`draft` по умолчанию равен `true`, `demo` — `false`.

Любая тестовая запись имеет `demo: true`, заголовок с `DEMO: ` и оба ключа с
префиксом `demo-`. Все 20 включённых примеров — вымышленные тестовые данные.
Они не устанавливают факты о вселенной NAITMOR. Для канона создавайте отдельные записи
с новыми ключами, а не переименовывайте DEMO и не отключайте их маркировку.

`getArchiveEntries()` исключает и черновики, и DEMO, даже если у DEMO отключить `draft`.
`getPreviewEntries()` — явно отдельный редакционный API. Коллекции сами не создают
страницы: интерфейс и маршруты материалов относятся к следующему этапу.

## Связи

Ссылки в полях задаются строками `ru/<entryKey>` или `en/<entryKey>`.
После валидации они становятся типизированными объектами `{ collection, id }`,
структурно совместимыми с API Astro. Проверяется существование записи, совпадение
языка и допустимость типа цели. В `related` доступны массивы с именами всех семи коллекций.

Например:

```yaml
related:
  characters: [ru/demo-character-alpha]
  timeline: [ru/demo-event]
  music: [ru/demo-album]
```

В тексте можно использовать семантические ссылки:

```md
[Тестовый персонаж](content:characters/ru/demo-character-alpha)
[Тестовое событие](content:timeline/ru/demo-event#demo)
```

Проверка разрешает их по записям и заголовкам. Это редакционный протокол:
на следующем этапе слой отображения должен разрешить запись и передать её в
`getContentUrl()`, чтобы получить обычный адрес. Не выводите `content:` в браузер
как готовый `href`. Также проверяются относительные ссылки на другие файлы записей
и локальные якоря. Ссылки между языками в тексте запрещены; перевод ищется по ключу.

Опубликованный канон не может ссылаться на черновик или DEMO. Самоссылки в полях
и циклы родительских статей лора запрещены. Циклы обычных смысловых связей допустимы.

## Изображения и аудио

Пути изображений задаются от корня проекта: `src/assets/images/<раздел>/<файл>`.
Поля `src` и `alt` обязательны, `credit` и `focalPoint` необязательны.
Изображение разрешается в метаданные Astro через `resolveContentImage()`;
будущий интерфейс сможет передать результат в `Image` или `Picture`.

Аудиопревью: `public/audio/previews/<файл>` либо HTTPS-адрес отдельного хранилища.
`resolveAudioUrl()` добавляет GitHub Pages base для локального превью.
Проверка требует существования всех указанных локальных медиа. В DEMO медиа не
указаны: вымышленных путей к отсутствующим файлам нет.

До готовности авторского изображения оставляйте запись галереи черновиком.
Публикуемая каноническая карточка галереи требует изображение. Аудиофайл у трека
не обязателен: можно указать только ссылки на музыкальные площадки.

## Проверка и выпуск

```sh
npm run check:content
npm run check
npm run build
npm run check:pages
```

`check:content` проверяет схемы, язык, пути, граф связей, текстовые ссылки и локальные
медиа. `check` также запускает регрессионные тесты и Astro/TypeScript.
`predev` и `prebuild` запускают проверку до старта сервера и сборки.
После изменений во время разработки повторно выполните `npm run check`:
наблюдатель Astro обновляет схемы, но не заменяет полную проверку графа.

HTTPS-ссылки проверяются по синтаксису, а ссылки площадок — также по домену.
Доступность внешнего сервиса, региональные ограничения и состояние релиза
проверяются редактором отдельно. В текущих DEMO внешних URL нет.

Снятие `draft` делает запись доступной production-выборкам; само по себе оно не
публикует сайт. `publishedAt` и `releaseDate` являются метаданными, не расписанием
автоматической публикации. Workflow публикации по-прежнему запускается вручную.

CLASSIFIED — публичный сюжетный архив без реальной защиты доступа.
Черновики и DEMO также видны в публичном исходном репозитории.
